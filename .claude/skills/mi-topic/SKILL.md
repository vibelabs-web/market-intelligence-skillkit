# 주제 바꾸기

$ARGUMENTS 주제로 사례를 새로 만든다. 스킬과 도구는 고치지 않고 `project/` 만 바꾼다.

## 시작 전
`git status` 로 고치지 않은 변경을 확인하고, 있으면 커밋할지 묻는다. 기존 사례는 git 기록과 `project/_이전사례-<날짜>/` 에 남긴다. 기존 사례를 지우기 전에 사용자에게 알린다.

## 절차
1. **묻기.** 한 번에 하나씩, 3개 이내로 묻는다. 인수에 `바로` 가 있으면 묻지 않고 합리적으로 정한 뒤 무엇을 정했는지 보고한다.
   - 고객은 어떤 회사(가상)이고 무엇을 언제까지 결정하려 합니까?
   - 브리핑을 받을 사람 2~3명은 누구이고 각자 무엇을 결정합니까?
   - 비교할 시장 · 경쟁사 · 지역의 범위는 어디까지입니까?
2. **이름 점검.** 가상 회사 이름이 실제 회사와 겹치는지 검색한다. 겹치면 다른 이름을 쓴다. 실제 고객사 · 비공개 프로젝트 정보는 쓰지 않는다.
3. **브리프와 프로필.** `project/brief.md` 와 `project/people/<영문 id>.md` 를 지금 형식대로 쓴다. 프로필에는 결정할 일 · 결정 시점(날짜) · 권한 · 놀라고 싶지 않은 것 · 더 알아야 할 주체 · 안 받아도 되는 것 · 형식을 쓴다. 이전 사례의 프로필은 지운다.
4. **시장 근거.** `project/fact-pack/evidence-register.csv` 를 같은 머리글로 새로 쓴다. 12~20건, 수요 · 규제 · 경쟁 · 공급 영역을 고루 담는다.
   - **실제로 열어 확인한 페이지만** 쓴다. 검색 요약이나 기억으로 쓰지 않는다. `quote` 에 원문을 짧게 그대로 옮기고 숫자는 quote 에 있어야 한다.
   - status 는 confirmed · proposed · uncertain. 초안 · 검토 단계와 낡은 자료를 구분해 `limitations` 에 쓴다. 모르는 날짜는 `unknown`.
   - 정의나 시점이 달라 숫자가 다른 실제 사례가 있으면 둘 다 넣고 `conflict_with` 로 잇는다.
   - CSV 는 파이썬 csv 모듈로 쓴다.
5. **내부 자료.** `project/fact-pack/internal-data.csv` 를 같은 머리글로 새로 쓴다. I-001 부터 10~15건. 판단에 쓸 금액 · 물량 · 재고 · 전환 이력 · 방식별 비용을 넣고 `synthetic` 은 true. 브리프의 내부 자료 표와 같은 값으로 맞춘다.
6. **점검.** `python3 tools/check_brief.py --help` 가 돌아가는지와 CSV 가 읽히는지 확인하고, `project/fact-pack/notes.md` 에 찾지 못한 것 · 상충 사례 · 믿기 어려운 행을 쓴다.

## 끝나면
받는 사람 목록, 근거 건수(영역별), 찾지 못한 것, 다음 명령 `/mi-brief <id> <id>-01` 을 알린다.

## 완료 조건
모든 E- 행에 실제 URL 과 원문 인용이 있다. 사람 수만큼 프로필이 있다. 지어낸 시장 수치가 없다.

## 실패하면
근거가 6건 미만이거나 결정을 가를 자료를 찾지 못하면 만든 것을 보여 주고, 주제를 좁히거나 자료를 직접 달라고 말한다. 숫자를 지어내 채우지 않는다.

## 권한
쓰기는 `project/` 만. 웹은 공개 자료만 읽는다. 로그인 · 유료 자료를 쓰지 않는다.
