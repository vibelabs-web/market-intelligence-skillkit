# 평가기 측정

## 입력
`golden/*.jsonl` · 코드 검사 `tools/check_brief.py` · `tools/agreement.py`.

## 절차
1. 코드 검사를 돌려 규칙 사례를 판정한다.
2. LLM 사례는 새 컨텍스트에서 N번(기본 3) 판정해 `runs/judge-<날짜>/` 에 저장한다.
3. `tools/agreement.py` 로 사람과의 일치율 · 반복 간 안정성 · 불일치 목록을 낸다.
4. 불일치를 평가기 오류 / 루브릭 모호 / 사람 판정 재검토로 나눈다. 평가기를 맞추려고 골든을 고치지 않는다.

## 측정하는 것
문장이 같은가가 아닙니다. **숫자 · 출처는 항상 일치, 합격 · 불합격 판정은 반복해도 일치, 권고 방향은 허용 범위 안**을 봅니다.

## 실패하면
일치율이 낮으면 평가기 문구를 몇 번 고치기 전에 불일치 3건을 사람에게 보여 기준이 명확한지부터 확인한다.

## 권한
골든을 고치지 않는다. 시장 진출 판단을 자동 승인하지 않는다.
