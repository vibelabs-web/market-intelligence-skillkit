# 스킬 깎기

## 입력
사람이 말하는 판단 · `runs/<run-id>/brief-<역할>.md` · `project/rubric.md` · `.claude/skills/` · `my/lens.md` · `shave-log.md`.

## 절차
1. **판단을 기록한다.** 평가자의 말에서 문장 · 판정 · 이유를 뽑아 `reviews/labels.csv` 에 한 줄씩 넣고 보여 준다. 평가자의 판단을 바꾸거나 좋게 고쳐 적지 않는다.
2. **원인을 가른다.** 사실이 없었나(근거) · 논리가 약했나(mi-strategy) · 독자에 안 맞았나(mi-briefing) · 기준이 틀렸나(rubric) · 이 사람의 관점인가(my/lens).
3. **고칠 곳 하나만 제안한다.** 바꾸기 전 · 후 문구와 기대 효과를 보여 주고 사람의 승인을 받는다. 특정 사례의 답을 스킬에 적지 않고, 다른 사례에도 통하는 규칙으로 쓴다.
4. **고치고 다시 돌린다.** 승인 뒤 고치고, 그 단계부터 다시 돌려 `runs/<새 run-id>/` 에 저장한다. 입력은 그대로 둔다.
5. **비교한다.** 같은 문장 · 항목이 어떻게 달라졌는지 보여 주고, 사람이 다시 판정하게 한다. 나빠진 곳도 말한다.
6. **남긴다.** `shave-log.md` 에 한 줄 추가하고, git 저장소면 고친 파일만 커밋한다.

## 완료 조건
한 바퀴에 고친 곳이 하나이고, 사람의 전후 판정이 기록에 있다.

## 실패하면
같은 항목을 두 번 고쳐도 판정이 안 바뀌면 멈추고 원인(자료 부족 · 기준 모호 · 모델 한계)을 말한다. 점수를 올리려고 루브릭을 느슨하게 하자고 제안하지 않는다.

## 권한
사람 승인 없이 스킬 · 루브릭을 고치지 않는다.
