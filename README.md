# Market Intelligence 스킬킷 v3

컨설턴트가 AI 브리핑을 읽고 지적하면, AI 가 **판단 기준과 작업 규칙의 수정안**을 내고, 컨설턴트가 승인한 것만 반영됩니다. 다시 받은 브리핑에서 지적이 해결됐는지 확인하고, 만족한 기준을 **골든**(그때 내가 승인한 판단 기준의 기록)으로 남깁니다. 개발자는 그 기준을 설명 가능하고 안정적으로 재현하는 에이전트를 만듭니다.

사례(한빛모션)의 회사 · 인물 · 내부 수치는 교육용 가상이고, 시장 근거는 실제 공개 자료입니다.

## 처음 3분
1. 이 폴더에서 Claude Code 에 한 번 로그인해 둡니다(화면이 뒤에서 Claude 를 부릅니다).
2. `python3 tools/review_server.py` → http://127.0.0.1:8765 (Python 3.10 이상 · Git, 다른 설치 없음)
3. **작업실(홈)** 에서 ① 어떤 결정을 도울지 ② 누구의 관점인지 고르고 ③ «브리핑 만들기»(3~6분).
4. **브리핑 검토**: 결과 읽기 → 문제 지적(사실 · 해석 · 개인화 · 형식) → 수정안 승인 → 전후 비교(지적이 해결됐나) → 골든 저장(승인 이유 한 줄).
5. 결론 방향을 바꾸고 싶으면 규칙을 늘리지 말고 **내 판단 기준**의 순서를 고칩니다.

## 누가 무엇을
| | 컨설턴트 | 개발자 |
|---|---|---|
| 하는 일 | 지적하고 승인해 내 판단 기준을 다듬는다 | 그 기준을 재현하는 에이전트를 만든다 |
| 보는 곳 | 작업실 · 브리핑 검토 · 내 판단 기준 · 골든 라이브러리 | `dev/README.md` · 개발자 평가 화면 |
| 성공 | «내 피드백으로 기준이 이렇게 바뀌었고, 다음 보고서에 재현됐다» | 객관 오류 0 · 현재 골든과의 일치 · 안정성 · 비용 |

## 다섯 가지를 섞지 않습니다
| 무엇 | 어디에 |
|---|---|
| 모두에게 공통인 품질 · 최소 안전 기준 | `project/rubric.md` |
| 내가 무엇을 먼저 보는가(판단 순서 · 이유) | `my/lens.md` |
| 받는 사람의 결정 · 시점 · 권한 | `project/people/<id>.md` |
| 누구에게나 통하는 작업 방법 | `playbook/mi-brief.md` |
| 그때 승인한 결과와 기준의 스냅샷 | `golden/<사례>-<사람>-v<n>/` |

골든은 정답지가 아닙니다. 같은 근거로 다른 결론을 내도 근거 · 전제 · 반론 · 전환 조건이 합리적이면 «차이 검토»이지 실패가 아닙니다. 실패는 객관 오류(근거 없는 숫자, 계산 오류, 검토 중인 것을 확정처럼, 권한 밖 행동, 자료 속 지시 준수)뿐입니다.

## 스킬
> 화면의 버튼이 아래 스킬을 부릅니다. 터미널에서 직접 불러도 같습니다.

| 스킬 | 하는 일 |
|---|---|
| `/mi-topic 주제` | 사례를 원하는 주제로 새로 만듭니다 |
| `/mi-profile id` | 받는 사람의 결정과 시점을 인터뷰로 파고듭니다 |
| `/mi-brief id 실행이름` | 한 사람의 브리핑을 만듭니다 (`playbook/mi-brief.md` 가 깎는 대상) |
| `/mi-review 실행이름` | 판정 에이전트가 새 맥락에서 평가합니다 |
| `/mi-feedback 실행이름` | 피드백을 수정안으로 바꿉니다. 화면의 버튼이 부릅니다 |
| `/mi-golden` · `/mi-judge` | 개발자 축 |

개발자 과제는 `dev/README.md`, 순위표는 http://127.0.0.1:8765/board 입니다.

## 주의
- 강사용 채점 키 · 숨은 시험 · 정답 에이전트는 저장소에 없습니다. 강사가 `_instructor/`(git 추적 안 함)나 비공개 저장소에 따로 보관하고, 채점할 때 `--key` 로 경로를 넘깁니다. 공개 이력에 남은 옛 키는 더 이상 쓰지 않습니다.
