# Market Intelligence 워크벤치 v4

컨설턴트가 **결정할 질문**을 정하면 그 방향으로 **새로 리서치**하고, 받는 사람마다 브리핑을 만듭니다. 컨설턴트가 브리핑을 읽고 지적하면 AI 가 **판단 기준과 작업 규칙의 수정안**을 내고, 승인한 것만 반영됩니다. 다시 받은 브리핑에서 지적이 해결됐는지 확인하고, 만족한 결과를 **골든**(그때 승인한 판단 기준의 기록)으로 남깁니다. 개발자는 그 판단을 설명 가능하고 안정적으로 재현하는 에이전트를 만듭니다.

리서치한 자료는 **지식 DB**(SQLite)에 쌓이고 개념별로 정리됩니다. 다음 프로젝트는 지식 DB 에서 아는 자료를 먼저 찾고, 빈 곳만 새로 조사합니다.

## 처음 3분
1. Node 22 이상과 Claude Code CLI 를 설치하고 `claude` 로 한 번 로그인해 둡니다. 앱이 뒤에서 `claude -p` 를 부르므로 **Claude Code 를 열어 둘 필요는 없습니다.**
2. `npm install` → `npm start` → http://127.0.0.1:8765
3. **+ 새 프로젝트**: 결정 질문 → 받는 사람(역할) → 조사 범위 → 우리 회사 숫자(선택) → 리서치 시작(10~30분, 검색어와 연 페이지가 실시간으로 보입니다).
4. **프로젝트**: 받는 사람을 고르고 «브리핑 만들기»(2~4분). «미확인» 칸은 아는 대로 고칩니다.
5. **브리핑 검토**: 읽기 → 문장을 끌어 지적(사실 · 해석 · 개인화 · 형식) → 기준 수정안 승인 → 다시 만들기 → 지난 지적이 해결됐나 표시 → 꼭 보낼 · 절대 뺄 근거 정하기 → 골든 저장(승인 이유 한 줄).
6. 결론 방향을 바꾸고 싶으면 규칙을 늘리지 말고 **내 판단 기준**의 순서를 고칩니다.

개발할 때는 `npm run dev`(서버 + 화면 자동 새로고침, http://127.0.0.1:5173), 시험은 `npm test` 와 `cd tools && python3 -m unittest test_tools` 입니다.

|---|---|---|
| 하는 일 | 리서치 방향을 정하고, 지적하고 승인해 내 판단 기준을 다듬는다 | 그 판단을 재현하는 에이전트를 만든다 |

## 섞지 않는 것
| 무엇 | 어디에 |
|---|---|
| 모두에게 공통인 품질 · 최소 안전 기준 | `project/rubric.md` |
| 내가 무엇을 먼저 보는가(판단 순서 · 이유) | `my/lens.md` |
| 누구에게나 통하는 작업 방법 | `playbook/mi-brief.md` |
| 받는 사람의 결정 · 시점 · 권한 | `data/projects/<id>/people/<역할>.md` |
| 리서치한 자료 · 개념 · 출처 | `data/mi.db` (화면의 «지식 DB» 에서 조회 · 읽기 전용 SQL) |
| 그때 승인한 결과와 기준의 스냅샷 | `data/golden/<프로젝트>-<역할>-v<n>/` |

`data/` 는 git 에 올리지 않습니다. 기준 문서(`my/lens.md` · `playbook/mi-brief.md` · `project/rubric.md`)를 승인으로 고치면 git 커밋으로 남고, 화면에서 되돌릴 수 있습니다.

골든은 정답지가 아닙니다. 같은 근거로 다른 결론을 내도 근거 · 전제 · 반론 · 전환 조건이 합리적이면 «차이 검토»이지 실패가 아닙니다. 실패는 객관 오류(근거 없는 숫자, 계산 오류, 불확실한 것을 확정처럼, 권한 밖 행동, 자료 속 지시 준수)뿐입니다.

## 구조
| 폴더 | 내용 |
|---|---|
| `server/` | Node · TypeScript(Fastify). `src/llm/claude.ts` 가 `claude -p` 를 부르는 유일한 곳, `src/db/knowledge.ts` 가 지식 DB |
| `web/` | React · Vite · Tailwind 화면 |
| `.claude/skills/` | 각 작업의 지시문(리서치 `mi-topic` · 검토 `mi-review` · 수정안 `mi-feedback` …). 서버가 프롬프트로 읽습니다 |
| `tools/` | 개발자용 채점 · 점검 CLI(Python) |

설정: `MI_MODEL`(기본 `claude-sonnet-5-5`) · `MI_DATA`(데이터 폴더) · `MI_RESEARCH_BUDGET`(리서치 1회 예산, 달러, 기본 6) · `MI_CLAUDE_BIN`.

## 주의
- 실제 고객 정보를 넣지 마세요. 받는 사람은 역할 이름만 씁니다. AI 는 회사 이름과 회사 숫자를 지어내지 않습니다.
- 리서치 자료는 그날 연 공개 페이지 기준입니다. 수업 전에 바뀔 수 있는 규제 · 관세는 다시 확인하세요.
- 강사용 채점 키는 저장소에 없습니다. 강사가 따로 보관하고 채점할 때 `--key` 로 넘깁니다.
